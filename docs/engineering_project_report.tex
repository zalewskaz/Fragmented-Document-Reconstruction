\subsection{2. One-Sentence Engineering / Research Problem
Formulation}\label{one-sentence-engineering-research-problem-formulation}

\begin{quote}
\emph{``The objective of this project is to design, implement, and
evaluate a software system capable of reconstructing fragmented
(shredded or torn) documents based on an image of their pieces,
supported by a dedicated document-splitting module for synthetic dataset
generation and testing.''}
\end{quote}

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{3. Project Scope: MVP vs.~Future Work (Scope
Management)}\label{project-scope-mvp-vs.-future-work-scope-management}

\subsubsection{3.1. Minimum Viable Product (MVP -- Passing
Scope)}\label{minimum-viable-product-mvp-passing-scope}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Document Splitting Module (Module 1):}

  \begin{itemize}
  \tightlist
  \item
    Supports single and batch mode processing.
  \item
    Allows users to split document images using various algorithms,
    preview piece borders, re-generate if needed, and apply random
    rotations and non-overlapping background placement.
  \item
    Saves the generated fragments locally.
  \end{itemize}
\item
  \textbf{Document Reconstruction Module (Module 2):}

  \begin{itemize}
  \tightlist
  \item
    Extracts individual fragments from an input image (single and batch
    mode).
  \item
    Reconstructs original documents using selectable or automated
    algorithms.
  \item
    Displays the reconstructed output, allows iterative refinement
    (adjusting time/algorithm), and saves the final result locally.
  \end{itemize}
\end{enumerate}

\subsubsection{3.2. Out of Scope (Future
Work)}\label{out-of-scope-future-work}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Integration with external cloud storage providers or dedicated mobile
  applications.
\end{enumerate}

\subsection{4. Functional Requirements (User Stories \& Acceptance
Criteria)}\label{functional-requirements-user-stories-acceptance-criteria}

\subsubsection{\texorpdfstring{\textbf{US-01: Ingestion of a Single
Telemetry Data
Point}}{US-01: Ingestion of a Single Telemetry Data Point}}\label{us-01-ingestion-of-a-single-telemetry-data-point}

\begin{itemize}
\tightlist
\item
  \textbf{As an:} External system (e.g., IoT sensor / telemetry script),
\item
  \textbf{I want to:} Submit a measurement with a timestamp and numeric
  value via the \texttt{POST\ /api/v1/metrics} endpoint,
\item
  \textbf{So that:} The data is validated, stored in the time-series
  database, and forwarded to the analytical engine.
\end{itemize}

\begin{quote}
\textbf{Acceptance Criteria (Gherkin):}

\begin{itemize}
\tightlist
\item
  \textbf{Given:} A running and authenticated ingestion service,
\item
  \textbf{When:} The client sends a \texttt{POST} request with a valid
  JSON payload
  \texttt{\{\ "sensor\_id":\ "temp-01",\ "timestamp":\ 1729000000,\ "value":\ 24.5\ \}},
\item
  \textbf{Then:} The system returns response status
  \texttt{201\ Created} in \(\le 50\) ms, and the record is persisted in
  the TimescaleDB hypertable.
\item
  \textbf{Scenario (Invalid data):}
\item
  \textbf{When:} The client sends a request with a negative timestamp or
  a missing \texttt{value} field,
\item
  \textbf{Then:} The system rejects the request with HTTP
  \texttt{422\ Unprocessable\ Entity} containing a detailed validation
  error message.
\end{itemize}
\end{quote}

feature and split value, where anomalies require fewer splits to
isolate. \\

the project fulfilling all foundational requirements for academic
project evaluation and defense. \\

distribution, indicating that 95\% of all incoming requests are served
in less than the specified duration. \\
\textbf{Rolling Z-Score} & A localized statistical metric representing
the number of standard deviations a given observation deviates from the
moving mean over a sliding temporal window. \\

operational measurement data from distributed sensors or agents to a
central receiving station. \\
